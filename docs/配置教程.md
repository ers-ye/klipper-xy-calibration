# 配置教程（中文）

本教程说明如何将皮带测频宏、加速度计数据流配置和可选的单 GPIO 对刀仪插件合并到 Klipper 项目。示例文件都是参考片段，需逐项合并，不是可直接 `include` 的配置覆盖文件。

## A. 配置手弹皮带频率采集

### 1. 检查运行环境

- 确认打印机中的加速度计已经在 Klipper 配置并可正常使用。
- 确认电脑上 Node.js 版本为 22.4 或更新版本（采集器使用 Node 内置 WebSocket，无需安装 npm 包）。
- 通过 SSH/文件管理或 Mainsail/Fluidd 下载方式备份当前 `printer.cfg`。修改前检查现有宏名，尤其是 `BELT_X`、`BELT_Y` 和 `OK`。

### 2. 合并宏

打开 `config/printer.cfg.belt-frequency-manual-merge.txt`，把 `[gcode_macro BELT_X]`、`[gcode_macro BELT_Y]` 和 `[gcode_macro OK]` 三段逐段合并到**现有** `printer.cfg`。不要复制文件外部注释作为 include，不要用这份片段替换完整配置。若有同名宏，先解决冲突，不能保留重复定义。

这三个宏只通过 `RESPOND` 输出位置提醒和开始/结束标记，不会移动机器。每次测量前，先确认打印机已回零、路径安全，再手动把喷头移动到 X=150、Y=150 mm；两条皮带都在该位置测。重启 Klipper 后，在 Console 输入 `BELT_X` 应看到位置提醒和 `B2K_BELT_SESSION_START_X`，输入 `OK` 应看到 `B2K_BELT_SESSION_FINISH`。这一验证只确认宏加载，不代表传感器采集器已运行。

### 3. 选择加速度计 profile

`config/accelerometers/` 中的 JSON 文件用于本地 Node 采集器，不是 Klipper 配置，也不会更改打印机设置。根据 Klipper 实际对象/API 选择：

| 文件 | 数据流 API | 备注 |
| --- | --- | --- |
| `lis2dw.json` | `lis2dw/dump_lis2dw` | 项目现场使用过的配置 |
| `lis3dh.json` | `lis2dw/dump_lis2dw` | 上游接口映射，未在本项目硬件验证 |
| `adxl345.json` | `adxl345/dump_adxl345` | 上游接口映射，未做硬件验证 |
| `mpu9250.json` | `mpu9250/dump_mpu9250` | 上游接口映射，未做硬件验证 |
| `icm20948.json` | `icm20948/dump_icm20948` | 上游接口映射，未做硬件验证 |

确认 profile 中的 `params.sensor` 与 Klipper 实例名完全相同。若是 `[adxl345 toolhead]`，实例名可能不是默认的 `adxl345`。对 Klipper fork，应在目标机的 Klipper 源码/API 中核对方法名和消息结构，不能仅因 profile 存在就假设兼容。

### 4. 自定义 profile

复制 `config/accelerometers/custom.example.json` 到本地 JSON 文件后编辑：

- `method`：Klipper 数据流 RPC 方法。
- `params.sensor`：已配置的传感器对象实例名。
- `data_path`、`header_path`：响应中样本数组和表头的位置。
- `sample_columns`：样本时间戳及 XYZ 列索引。

采集器需要将样本适配为 `[timestamp, x, y, z]` 四个数值。若 API 数据层级或数据布局不同，仅修改 sensor 名称并不够，还需要改 `tools/sensor_config.mjs` 的映射代码。使用自定义配置：

```powershell
node tools/belt_session.mjs --host=YOUR_PRINTER_HOST --sensor-config=path\to\my-sensor.json
```

### 5. 启动与验证

在项目根目录启动本地采集器：

```powershell
node tools/belt_session.mjs --host=YOUR_PRINTER_HOST --sensor-config=config/accelerometers/lis2dw.json
```

`--host` 是运行 Moonraker 的主机名或 IP。也可设置 `$env:B2K_PRINTER_HOST`，但不要把私人地址写进公开配置文件、截图或提交记录。看到“已连接”和 profile 名称后，在 Mainsail/Fluidd Console 使用 `BELT_X`/`BELT_Y` 开始，手弹后实时观察频率，输入 `OK` 保存 CSV。流程详见[使用教程](使用教程.md)。

### 6. 宏不输出频率时排查

宏自身只输出起止标记；实时频率由本地 Node 进程读取 Klipper 流并通过 Moonraker 回显。因此检查：

1. 本地终端进程仍在运行并显示成功连接。
2. 主机地址正确，Moonraker 与 Klipper 的 WebSocket 可用。
3. profile 的 API 方法和对象名与目标 Klipper 相符。
4. Console 已输入正确的 `BELT_X`/`BELT_Y` 标记；一次仅运行一个采集会话。
5. 弹拨确实让加速度计采到足够的振动样本。错误、网络断开或消息映射不匹配时查看本地终端输出。

## B. 可选：配置单 GPIO 对刀仪事件插件

此部分用于共享单个机械微动开关的 X/Y/Z 事件记录，与皮带测频不同。只有一个物理开关时，只配置一个 `[gcode_button]`；`AXIS` 和 `DIRECTION` 由实验标记提供，不能从 GPIO 推断。

1. 确认目标 Klipper 代码树、版本和 extras 插件加载路径。
2. 在打印机主机 SSH 终端执行下列命令。`$HOME/klipper` 是常见目录示例；若不匹配，必须改成已确认的实际 Klipper 源码目录：

   ```sh
   git clone --depth 1 https://github.com/ers-ye/klipper-xy-calibration.git "$HOME/klipper-xy-calibration"
   export KLIPPER_DIR="$HOME/klipper"  # 修改为已确认的 Klipper 路径
   test -d "$KLIPPER_DIR/klippy/extras" || { echo "Klipper extras 目录不存在；请核对 KLIPPER_DIR" >&2; exit 1; }
   test ! -e "$KLIPPER_DIR/klippy/extras/b2k_xy_calibration.py" || { echo "插件文件已存在；为避免覆盖而停止" >&2; exit 1; }
   install -m 0644 "$HOME/klipper-xy-calibration/klippy/extras/b2k_xy_calibration.py" "$KLIPPER_DIR/klippy/extras/b2k_xy_calibration.py"
   ```

   命令只安装插件文件；不会改写配置、重启 Klipper 或执行运动。若目标文件已经存在，先检查原文件，不要直接覆盖。
3. 将 `config/printer.cfg.xy-calibration-manual-merge.txt` 中 `[b2k_xy_calibration]` 和唯一的 `[gcode_button b2k_probe]` 手动合并到现有 `printer.cfg`。
4. **只在核实主板引脚图、电平/上拉和开关接线后**，将 `<BOARD_GPIO_PLACEHOLDER>` 替换成实际引脚配置。此仓库不猜测 GPIO，也不提供三个独立开关配置。
5. 在 Mainsail/Fluidd 执行 Firmware Restart，检查日志中的配置/导入错误；再用 `QUERY_BUTTON BUTTON=b2k_probe` 在静止、安全情况下核实按下和释放逻辑。
6. 只有在操作者确认安全位置、间隙、行程和碰撞路径后，才可自行安排受控手动运动实验。插件不会发起运动；不要用 `FORCE_MOVE` 做常规校准。

回调得到的位置只标记为 `host_estimate`，不是 MCU 精确锁存位置。没有独立长度基准，只能分析重复定位误差，不能据此声称 20/50/100 mm 绝对运动比例误差。插件不会自动更改 `rotation_distance`、microsteps、加速度或其他运动参数。

## C. 回滚

如宏配置有冲突或需撤回，恢复修改前备份的 `printer.cfg` 并执行 Klipper Restart。插件若已复制到 Klipper extras，删除该单个插件文件后再重启。回滚前确认没有其他配置引用该插件或这些宏。
